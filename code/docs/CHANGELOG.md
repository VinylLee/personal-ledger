## 2026-11-11 交易明细可隐藏退款

- 勾选「隐藏退款回款及已退款支出」时隐藏退款回款与全额退款支出。部分退款按已确认分摊后的差额显示并计入合计。

## 2026-11-11 图表悬停与交易明细

- 悬停扇区或柱可查看金额，「其他」会列出合并分类及金额。
- 点击后按已应用的图表条件查看交易明细。明细显示流水金额和计入图表金额，清除图表筛选可返回之前的查询。

## 2026-11-11 交易明细可隐藏报销

- 「隐藏报销回款及已报销支出」开关可隐藏报销回款及已确认报销关联的支出，包括部分报销的支出。明细合计按可见记录重算。

## 2026-11-11 退款和报销沿用原支出分类

- 已确认关联的回款在明细、报表和图表中整笔归入原支出分类。原支出改类后同步，解除关联后显示回款自身分类。
- 净收支按到账日归集全额，纯收支按确认的分摊金额回溯扣减。未分摊的余额仍在复核页显示。
- 现有账本可在重新打开程序后直接读取这套分类规则。

## 2026-11-11 整体统计折合人民币

- 行为变化：收支报表和交易明细的汇总标签中，非 CNY 金额后追加「（≈ 人民币 X）」，并增加「全部折合人民币」合计行。单笔明细、图表、命令行报表和存储金额不折算。
- 汇率来源：`https://open.er-api.com/v6/latest/CNY`，无需 API Key；缓存在账本同目录 `exchange_rates.json`（默认 `output/`，不入库），有效期 24 小时。
- 刷新策略：先读缓存并立即显示；过期时先用旧值（标签注明「汇率缓存 YYYY-MM-DD」），后台再更新。只有完全没有缓存时才同步请求（超时 5 秒）。CNY-only 视图不联网。
- 失败降级：网络失败时使用旧缓存；无缓存则保留原金额并提示「汇率不可用，未折算非人民币金额」。缺少某币种汇率时该行不折算并在合计行注明。
- 隐私：请求只包含币种代码，不发送账本、交易、账户或筛选数据；缓存只含公开汇率。
- 涉及文件：`exchange.py`（新增）、`ledger_gui.py`、`README.md`、根 `README.md`、`docs/ARCHITECTURE.md`、`docs/DEVELOPMENT.md`、`docs/README.md`、`CLAUDE.md`、`.gitignore`。
- 验证方式：汇率解析/方向/缓存/TTL/失败降级的单元检查；账本副本上的无界面 GUI 检查（新鲜缓存、过期缓存、无缓存断网、CNY-only）；真实接口实测并与界面输出核对；`py_compile`、主窗口冒烟、`audit`。
- 兼容性：无 schema、`decisions` 或数据变化；不需要重建账本；不新增第三方依赖。

## 2026-11-11 交易明细支持多选批量编辑

- 行为变化：
  - 「交易明细」表格改为 Ctrl/Shift 多选；选 1 笔仍是单笔编辑，选 2 笔及以上打开「批量编辑 N 笔交易」。
  - 批量窗口对类型、分类、交易对方、说明、备注逐字段勾选；未勾选字段保留每笔原值，勾选后留空表示清空（类型/分类不可清空）。
  - 批量修改类型时校验流水方向；与已确认退款/报销关联冲突时只确认一次；跨渠道重复待确认、不计收支缺备注会在保存前拦截。
  - 保存时整体校验、只重建一次账本，刷新后保留选中、排序和滚动位置。
- 修复的既有问题：
  - 部分字段保存时以数据库中的有效类型/分类为准，避免已关联交易的旧分类规则导致重建失败，或悄悄改回未编辑的字段。
  - 「确认交易性质」改为合并旧规则，不再丢弃此前设置的说明和备注。
  - 方向校验统一为 `kind_conflicts_direction`，消除三处重复判断。
- 涉及文件：`ledger_gui.py`、`README.md`、`docs/`（新建）。
- 验证方式：`py_compile`；账本副本上的无界面回归（统一/部分字段、清空、方向冲突、空分类、单笔兼容、已关联交易只改备注、待复核确认后保留文字）；主窗口与对话框冒烟测试。
- 兼容性：`decisions` 格式未变，旧账本无需迁移。
