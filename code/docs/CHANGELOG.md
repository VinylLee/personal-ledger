## 2026-11-11 关键字兜底分类

- 行为变化：原本会落到「待分类」或「流出用途待判断」的流出交易，会再按交易对方、说明、商品说明和来源类型中的关键字归类。
  - 核心词：卫生院/医院→医疗，图文/打印→文娱，交通/轨道/出行/滴滴→交通，肯德基/老乡鸡等→餐饮。
  - 补充词：社区卫生、门诊、药房、门票、地铁、高铁、点餐、牛肉汤、火锅、串串、华莱士、寿喜烧等。
  - 现有分类（购物、车辆、生活缴费、住宿、教育、捐赠）也会参考交易对方，例如拼多多/淘宝→购物、桩小盟→车辆。
- 匹配规则：在兜底步骤中交易对方优先于说明；同一字段命中多个分类时保持原来的兜底结果（待分类或流出用途待判断）；匹配前剔除「交通银行」；结果写入 `rule = "关键字：<词>"`。
- 当前数据下已有分类、人工复核和关联结果均未改变；需重建账本后生效。
- 试算与实测：当前 283 笔待分类中 137 笔完成归类（购物 68、餐饮 49、文娱 10、交通 5、医疗 3、车辆 2），其余 146 笔保持原状态（本批均为待分类）。
- 涉及文件：`accounting.py`、`README.md`、`docs/ARCHITECTURE.md`、`docs/DEVELOPMENT.md`。
- 验证方式：正反例单元检查（含交通银行、跨类歧义、交易对方优先、说明命中）；账本副本重建逐条比对，仅原「待分类」记录变化，关联与 `decisions` 未变；`audit` 通过。
- 兼容性：`decisions` 格式不变，旧账本无需迁移；已分类交易不受影响。

## 2026-11-11 公开仓库准备：个人姓名移入本地私有规则

- 行为变化：`accounting.apply_counterparty_rules` 不再硬编码真实姓名，改为读取可选的 `local_rules.py` 中的 `SELF_NAMES`；文件缺失时规则自动禁用。命中本人户名的流水仍归为「账户划转」。
- 新增：`local_rules.example.py` 模板；`local_rules.py` 加入 `.gitignore`。
- 涉及文件：`accounting.py`、`README.md`、`local_rules.example.py`、`docs/ARCHITECTURE.md`、`docs/DEVELOPMENT.md`。
- 验证方式：`py_compile`；单元式脚本确认有本地规则时识别为账户划转、移除规则后不再识别。
- 兼容性：本地已有 `local_rules.py` 时行为不变；全新克隆需按 README 复制模板并填写姓名。
- 隐私注意：真实账本 `output/`、原始账单 `交易记录/` 和 `local_rules.py` 均不得提交。

## 2026-11-11 交易明细支持多选批量编辑

- 行为变化：
  - 「交易明细」表格改为 Ctrl/Shift 多选；选 1 笔仍是单笔编辑，选 2 笔及以上打开「批量编辑 N 笔交易」。
  - 批量窗口对类型、分类、交易对方、说明、备注逐字段勾选；未勾选字段保留每笔原值，勾选后留空表示清空（类型/分类不可清空）。
  - 批量修改类型时校验流水方向；与已确认退款/报销关联冲突时只确认一次；跨渠道重复待确认、不计收支缺备注会在保存前拦截。
  - 保存时整体校验、只重建一次账本，刷新后保留选中、排序和滚动位置。
- 修复的既有问题：
  - 部分字段保存时以数据库中的有效类型/分类为准，避免已关联交易的旧分类规则导致重建失败，或悄悄改回未编辑的字段。
  - 「确认交易性质」改为合并旧规则，不再丢弃此前设置的说明和备注。
  - 方向校验统一为 `kind_conflicts_direction`，消除三处重复判断。
- 涉及文件：`ledger_gui.py`、`README.md`、`docs/`（新建）。
- 验证方式：`py_compile`；账本副本上的无界面回归（统一/部分字段、清空、方向冲突、空分类、单笔兼容、已关联交易只改备注、待复核确认后保留文字）；主窗口与对话框冒烟测试。
- 兼容性：`decisions` 格式未变，旧账本无需迁移。
